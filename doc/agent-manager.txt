1. Introduction                                      *agent-manager-intro*

Agent Manager presents Codex and Claude agents in native Neovim buffers. Its
embedded Rust broker owns one live agent. Durable mode connects to a supervised,
owner-only Unix socket and keeps multiple agents alive across SSH and Neovim
restarts. M2 added safe interaction, M3 added the immutable `agent.manager` UX
contracts, M4 added replay/resync, metadata persistence, and writer isolation,
and M5 added a reproducible, checksummed, attested release with exact production
configuration pins.

2. Setup                                              *agent-manager-setup*

>lua
    require("agent_manager").setup({
      broker = {
        command = { "/path/to/agent-manager-broker", "serve" },
      },
      providers = {
        codex = {
          executable = "/path/to/codex",
          model = "gpt-5.4", -- optional initial default
          effort = "high",  -- optional initial default
        },
        claude = {
          python = "/path/to/worker-runtime/bin/python",
          model = "sonnet", -- optional initial default
          effort = "high",  -- optional initial default
        },
      },
      worktrees = {
        lifecycle = "/path/to/zemrip-agent-workspace",
        allow_shared = false,
      },
      ui = {
        prompt_min_height = 3,
        prompt_max_height = 12,
        external_sessions = true,
        external_session_limit = 1000,
        conversation_markdown = true,
      },
    })
<

A source checkout discovers target/release or target/debug broker artifacts
and python/.venv/bin/python relative to the plugin root when present. A public
protocol revision check rejects a stale broker with rebuild guidance instead
of allowing a partially compatible UI. Startup never builds or installs
dependencies.

Durable mode requires an already supervised broker plus absolute executable
and socket paths:

>lua
    require("agent_manager").setup({
      broker = {
        mode = "durable",
        command = { "/home/ai/.local/bin/agent-manager-broker", "serve-durable" },
        socket = "/run/user/1000/agent-manager/broker.sock",
      },
      providers = {
        claude = {
          python = "/home/ai/.local/share/agent-manager/venv/bin/python",
        },
      },
    })
<

The durable client reconnects with capped backoff. Closing or tearing down the
view disconnects Neovim only; it never shuts down the supervised broker.

3. Commands                                        *agent-manager-commands*

                                                   *:AgentManager*
:AgentManager              Open or focus the dedicated workspace tab.

                                                   *:AgentManagerWorkflows*
:AgentManagerWorkflows     Open the long-running workflow checklist in that tab.
                          gs or gw opens Workflows from Sessions; gs returns.
                          Workflows and milestone phases start collapsed.
                          Each phase shows completed/total tasks. Expand a task
                          to browse its sessions; select a session for history.
                          The detail header shows that session's model/provider
                          and input/output tokens, including cached input.
                          Usage is not reported until saved by the queue;
                          cached input is already included in input tokens.
                          Enter toggles workflow/phase or inspects task/session.
                          l expands; h collapses or moves to the parent.
                          Tab switches panes, gr refreshes, q closes the view.
                          gp toggles the workflow's provider suite after active
                          sessions finish; gp again cancels a pending switch.
                          A session limit cancels the pending manual switch
                          and automatic fallback handles the interrupted stage.
                          Checked tasks retain completed work and sessions;
                          active tasks/sessions are highlighted when expanded.
                          This observer never resumes a session.
                          The external queue keeps running when Neovim closes.
                          Legacy/review transcripts may be unavailable; their
                          saved result evidence remains visible.

                                                   *:AgentManagerStart*
:AgentManagerStart [codex|claude]
                           Use the current project as a directory hint, select
                           a provider when omitted, then create a
                           lifecycle-managed task or resume an existing task
                           mapping. Durable mode may own multiple agents;
                           embedded mode owns one.

                                                   *:AgentManagerAttach*
:AgentManagerAttach        Select a broker agent or resumable provider session.

                                                   *:AgentManagerSend*
:AgentManagerSend [text]   Send a prompt, or focus the Conversation prompt box
                           without text.

                                                   *:AgentManagerSteer*
:AgentManagerSteer [text]  Add input to the selected active turn.

                                                   *:AgentManagerInterrupt*
:AgentManagerInterrupt     Confirm and interrupt the selected active turn.

                                                   *:AgentManagerFork*
:AgentManagerFork          Fork the selected idle or completed provider session.

                                                   *:AgentManagerArchive*
:AgentManagerArchive       Confirm and remove an inactive agent from the broker
                           registry without deleting provider history.

                                                   *:AgentManagerDelete*
:AgentManagerDelete        Confirm and permanently delete the selected provider
                           session history while preserving its worktree and
                           project files.

                                                   *:AgentManagerContext*
:AgentManagerContext       Queue an explicit buffer, range, diagnostic, or diff
                           snapshot for the selected agent's next input.

                                                   *:AgentManagerDiff*
:AgentManagerDiff          Show the workspace diff or resolve a dirty-buffer
                           conflict caused by an external agent edit.

                                                   *:AgentManagerHealth*
:AgentManagerHealth        Run |:checkhealth| for Agent Manager.

                                                   *:AgentManagerClose*
:AgentManagerClose         Close the view without interrupting the agent.

4. Workspace                                      *agent-manager-workspace*

The native workspace opens with focus in the directory and uses directory,
conversation, and bottom input windows. In the directory, 1 shows sessions and
2 shows workflows. In the bottom window, 1 shows the prompt and 2 shows the
shortcut guide.
Normal-mode we expands the current pane; pressing we again restores the previous
split sizes. Expanded Conversation keeps its prompt box. Press <Esc> to leave
Insert mode before using we or w1/w2. Prompt Up/Down move by visible wrapped
lines in both Normal and Insert modes.

Prompts submitted while running are queued per session and run in order after
successful completion. Interrupt/failure cancels queued follow-ups. Up to 32
prompts can wait in broker memory; they do not survive a broker restart. ts
still steers the current turn. Token totals appear under Usage in the directory.

Conversation labels assistant replies with the model name in blue. The label
is a level-two Markdown heading (`## model-name`) followed by a blank line, so
the reply is its own Markdown block. User messages have no YOU heading and use
purple text. Per-label font sizes are unavailable in the native Neovim text
grid.

The transcript is Markdown source and keeps provider text verbatim. Its
buffer filetype stays `agent-manager-conversation`, registered as a dialect of
the bundled `markdown` treesitter parser, so headings, code fences, tables, and
inline code take the colorscheme's Markdown highlights. An installed
render-markdown.nvim draws the transcript through Chrome's pane integration.
Without Chrome, list `agent-manager-conversation` and `agent-manager-agents`
in its `file_types`; Agent Manager's own message highlights are applied
above the renderer's and stay in effect. Set `ui.conversation_markdown = false`
to keep the transcript unparsed.

The df command opens a workspace diff snapshot in Conversation; repeat df to refresh.

Wide displays show the directory and conversation panes. Narrow displays may use
<Tab> and <S-Tab> to cycle panes.

The Agents pane is a lazy filesystem tree rooted at the full home directory
(for example, `/home/ai/`). Directories appear independently of
session state. Known managed repositories, broker-owned agents, and active or
saved standalone Codex/Claude sessions are overlaid beneath their directories.
Directories containing sessions sort before directories without sessions.
Directory contents begin collapsed. Rows are flat, with Markdown --- rules
between top-level directory blocks. Each visible directory's direct sessions
remain beneath a highlighted, independently collapsible "Sessions" row even
while that directory's subdirectories are collapsed. The first five
sessions appear initially; selecting the group cycles through all, none, and
five. They are ordered by most recent activity across providers.
Historical paths carry `[past cwd]`; a new session cannot start there.
The project where Agent Manager was opened carries a `[cwd]` marker; repository
directories learned from managed sessions or explicit inventory carry
`[repo]`. Place the cursor on a directory and press `sn` to use it as the
start-flow hint. Canonical clones and managed worktrees use the required
`~/<repo>` and `~/worktrees/<repo>/<task>` layout without first running the
repository-wide lifecycle audit; the lifecycle claim still validates the
candidate before launch. Nonstandard paths fall back to explicit inventory.
Choose a provider, then choose from its numbered model catalog. "Default" is
the first and initially highlighted choice, so <CR> accepts it immediately. It
uses the configured or most recently selected model when present, otherwise the
provider default. Focus then moves to the persistent prompt box at the bottom
of Conversation; no title is requested. The box wraps words, expands from
ui.prompt_min_height up to ui.prompt_max_height. Use <C-j> to insert a newline.
Submitting the first prompt creates the managed worktree using a generated task
ID, which becomes the session title. Submitted text stays in the prompt until
the broker accepts it; accepted text clears and returns the box to its minimum
height, while failed submissions remain available to edit and retry.

Opening a saved session reuses its workspace without asking for a name. The
provider/session association is saved in stdpath('state') under
agent-manager/session-workspaces/ so an editor restart or stale provider cwd
cannot assign another workspace. Older canonical-only sessions receive a stable
automatic task ID. Missing worktrees or conflicting/unreadable associations
require recovery; resume never creates a replacement for a saved mapping.
Codex CLI sessions outside Git (for example, in the home directory) resume in
their original directory without lifecycle inventory when no managed association
exists. This Codex-only resume is permitted with shared-checkout starts disabled;
Git checkouts, the managed worktree namespace, and new starts retain that policy.

The key at the top maps `● Codex` and `◆ Claude` plus `● active`, `○ resume`,
`? check`, and `× ended` to their semantic colors. Session rows show only the
two symbols and title. Active external rows remain read-only while the
originating terminal owns them. The tree is refreshed when the workspace opens
and with `gr`. Set `ui.external_sessions` to false to hide external CLI
sessions; `ui.external_session_limit` caps each provider query from 1 to 1000.

    directory: 1 sessions / 2 workflows
    bottom:    1 prompt / 2 shortcuts
    sn / so start a session / open or continue one
    sf / sa fork / archive a session
    am / ae change model / effort for the next prompt
    tp / ts prompt / steer the selected agent
    ti / tc confirm interrupt / queue explicit editor context
    df / ds show a focused diff / delete focused provider history
    ga/gc/gt focus directory / Conversation / shortcuts
    gr      refresh the filesystem and provider sessions
    y / n   yes/allow or no/deny only the focused human request
    <CR>    send in the prompt box; otherwise toggle/open/answer the focused row
    <C-j>   insert a newline in the prompt box
    h / l   collapse / expand a directory
    we      toggle expanded pane and restore previous split sizes
    w1/w2 focus directory / Conversation, preserving expanded mode
    <Tab>   cycle panes
    ? / g?  show mapping help
    q       close the workspace view

Mappings are buffer-local. If which-key.nvim is available, `a`, `d`, `g`, `s`,
and `t` open buffer-local groups without `<leader>`; Agent Manager does not change
which-key setup or the user's global/leader mappings. Closing the view does not
approve, interrupt, or delete provider state. A provider approval or question
opens a dedicated decision buffer that normal streaming redraws do not replace.

5. Safety                                            *agent-manager-safety*

Live prompts may consume provider quota. Credentials stay in the installed
provider runtimes and never enter Agent Manager configuration. Human callbacks
fail closed on timeout, cancellation, disconnect, malformed response, or
shutdown. The UI exposes only decisions advertised for the pending request.

Editor context is explicit and one-shot. Unsaved snapshots are marked but never
written automatically. An external change never reloads a modified buffer; use
|:AgentManagerDiff| to inspect, compare, explicitly reload, or keep it.

Embedded state ends when its broker exits and supports one live runtime. The
durable broker persists provider identity and transcript-free metadata, replays
retained events, and reloads provider history when replay is too old. Normal
starts select a registered repository, then generate a task ID when the first
prompt is submitted. The broker asks the
installed lifecycle authority to claim or resume the matching `agent/**`
branch, lease, and linked worktree; it never duplicates that Git logic.

Shared-checkout starts are disabled by default. An administrator may set
`worktrees.allow_shared = true`; the embedded broker enforces the resulting
policy, while durable service policy is configured on the supervised broker.
Agent Manager exposes no worktree reset, checkout deletion, force-clean, or
garbage-collection control. `ds` and |:AgentManagerDelete| are limited to the
provider's saved session history. They require confirmation, refuse active
sessions and pending human requests, retire an idle manager-owned runtime, hand
off its managed lease, and always preserve the worktree, branch, and project
files. A fork keeps its source as a disconnected summary so writer ownership
remains explicit.

Codex and Claude sessions record the actual runtime versions returned by their
startup handshakes and the compatibility profile used to validate them. The
Codex stable-v1 profile accepts the reviewed 0.152.0 schema baseline and newer
stable releases with experimental APIs disabled. Running processes are not
hot-upgraded; resuming a persisted session uses the currently configured
compatible runtime.

External CLI discovery projects metadata only. Prompt previews and tool
payloads do not cross into the Neovim model. Opening the workspace and `gr`
refresh session metadata without running full lifecycle inventory; callers can
request that inventory explicitly when they need every registered repository
and task mapping. Agent Manager does not attach to, resume, interrupt, or
otherwise seize a session while its standalone CLI owns the provider writer.

6. UX integration                                       *agent-manager-ux*

Native presentation has no UX dependency. When UX Foundation schema v1 is on
the runtimepath, Agent Manager registers the immutable `agent.manager` manifest
and Foundation owns the AgentManager* groups and profile replay. UX Styling
discovers `ux_styling_adapter.agent_manager` without loading the Agent Manager
runtime, starting the broker, or reading domain data.

When Chrome provides ux_chrome.components, navigation rows use shared padding,
header colors, and display-cell truncation. Foundation settings live under
ux.chrome.components with overrides at
ux.chrome.component.agent.manager.navigation. Live edits reformat cached rows
without refreshing the broker or scanning directories. Tree connectors retain
their application-defined indentation. Action targets retain full identities
even when displayed text truncates. Older Chrome and standalone installations
keep native presentation.

Agent Manager does not write tabline, statusline, winbar, statuscolumn, fold,
or scrollbar expressions owned by UX Chrome. Cached consumers may call:

>lua
    require("agent_manager").status()
    require("agent_manager").running_count()
    require("agent_manager").pending_approval_count()
<

These reads do not initialize the runtime. A scheduled
`User AgentManagerStateChanged` event carries running_count,
pending_approval_count, agent_ids, and a non-sensitive reason. It never carries
prompt text, messages, tool payloads, or credentials. The current Chrome
contract has no public segment API, so Agent Manager does not use Chrome
internals. UX Panels is not available at the M3 compatibility pins; the view
backend remains native and |:AgentManagerHealth| reports that choice.

7. Release and durable install                     *agent-manager-release*

The v0.1.0 production asset targets Linux x86_64. It contains the native broker,
the exact relocatable Python 3.13 interpreter, and the private worker's
hash-locked packages. release.json pins
the source revision, broker and worker contracts, provider versions, UX
revisions, and clean-source marker. PAYLOAD.SHA256 covers the inner tree and
SHA256SUMS covers the archive. GitHub publishes keyless build attestations from
a verified signed annotated tag reachable from the default bluff branch.

The nvim-config Lazy build hook runs install-current.sh after the plugin is
installed or its release pin changes. It reuses a verified active runtime or
downloads and activates immutable versioned paths without Cargo, uv, pip, or
dependency resolution on the destination. It does not run during DevPlugins.
Hosts that need sessions to survive Neovim exits can next run
ops/m4-durable-service/ in its documented order. The install phases are
idempotent and ship reverse-order paired undo.
